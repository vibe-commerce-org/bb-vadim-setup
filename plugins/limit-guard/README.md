# Сторож лимитов_vibecom 0.3.1

Last Updated: 2026-11-21

Папка и id плагина — `limit-guard`; в интерфейсе BB он называется Сторож лимитов_vibecom. Нужен bb 0.46 или новее.
Карточка **«Сторож лимитов»** — иконка в подвале боковой панели, рядом с настройками.

Плагин следит за недельными лимитами подписок и бюджетами платных моделей и не даёт треду упереться в потолок
посреди работы. Это пять независимых сторожей одного кода: у каждого свой выключатель, пороги и согласие.

| Сторож | По умолчанию | Что следит | Что делает |
|---|---|---|---|
| **Claude Code** | включён | недельный лимит подписки Claude | с 85 % переводит треды на Sonnet и снижает effort, с 93 % ходы ждут вашего согласия, идущие треды останавливаются |
| **Codex** | **выключен** | недельный лимит Codex (ChatGPT) | с 85 % снижает effort до `medium`, модель треда не трогает; с 93 % то же, что у Claude |
| **Gemini · Vertex** | включён | расход тредов Pi на `google-vertex/*`, доллары | недельный бюджет $50 |
| **Яндекс** | включён | расход тредов Pi на `yandex/*`, российские рубли (₽) | недельный бюджет 1 000 ₽ |
| **Cloud.ru** | включён | расход тредов Pi на `cloudru/*`, российские рубли (₽) | недельный бюджет 1 000 ₽ |

У бюджета Gemini есть ещё **автопереключение при ошибке 429**: тред Pi на `google-vertex/*` переходит на следующую модель
цепочки, упавший ход отправляется заново, модель с 429 отдыхает 30 минут и дольше, потом проба и возврат. Настройка
`geminiFallback` (по умолчанию включено), цепочка — `geminiFallbackChain` (id моделей Vertex через запятую, от сильной к слабой).

У бюджетов: на 80 % — предупреждение в карточке, на 100 % новые ходы Pi на моделях этого провайдера ждут вашего
согласия, идущие такие треды останавливаются. Неделя — календарная, с понедельника 00:00 по Москве. Расход — **оценка**
по ценам из `~/.pi/agent/models.json`, а не счёт провайдера.

## Что нужно, чтобы бюджеты считали

- Бюджеты считают только треды агента **Pi** и только по файлам его сессий. Нет Pi или моделей этого провайдера —
  блок остаётся на нуле.
- Расход берётся из поля `cost` каждой модели в `~/.pi/agent/models.json` (цена за миллион токенов). **В шаблоне
  `models/pi/models.json` комплекта цен нет**, поэтому у Яндекса и Cloud.ru блок покажет «расход не прочитан»,
  пока вы не впишете цены. Vertex в шаблонах комплекта нет совсем: Gemini через Vertex подключается отдельно.
- Ненужный бюджет выключается: `bb limit-guard off gemini` (или `yandex`, `cloudru`) или переключателем в карточке.
- Баланс счёта Яндекса показывается, если выполнить `setup/yandex-billing-viewer.md` (сервисный аккаунт только для
  чтения). Месячный расход Google в комплект не входит.

## Команды

Слово провайдера — **после** глагола: `claude`, `codex`, `gemini`, `yandex`, `cloudru`. Без слова команда относится к
Claude Code.

```bash
bb limit-guard status [claude|codex|gemini|yandex|cloudru] [--json]   # без слова — все сторожа
bb limit-guard on codex                  # включить сторожа Codex
bb limit-guard off [codex|gemini|yandex|cloudru]   # выключить: ничего не держит, не останавливает, не переключает
bb limit-guard resume [codex|gemini|yandex|cloudru]  # согласие продолжать после порога до сброса недели
bb limit-guard limit gemini|yandex|cloudru <сумма>   # недельный бюджет, например: limit yandex 1500
bb limit-guard restore-models [codex]    # вернуть тредам прежние модели (сторож выключен или стадия 0)
```

Согласие (`resume`) и выключение (`off`) — решения пользователя. Агентам в `~/.claude/settings.json` стоит запретить
эти команды правилами `Bash(bb limit-guard resume*)`, `Bash(bb limit-guard off*)`, `Bash(bb limit-guard on*)`,
`Bash(bb limit-guard limit*)` — слово провайдера стоит после глагола, поэтому они ловят и `off codex`.

## Настройки (`bb plugin config limit-guard`)

| Ключ | По умолчанию | Что |
|---|---|---|
| `sonnetPercent` / `stopPercent` | 85 / 93 | пороги Claude Code, % |
| `codexCheapPercent` / `codexStopPercent` | 85 / 93 | пороги Codex, % |
| `codexModel` | пусто — своя модель треда | модель Codex для экономного режима (`bb provider models codex`) |
| `codexEffort` | `medium` | effort Codex в экономном режиме |
| `geminiWeeklyUsd` / `yandexWeeklyRub` / `cloudruWeeklyRub` | 50 / 1000 / 1000 | недельные бюджеты |
| `geminiFallback` / `geminiFallbackChain` | да / цепочка Vertex | автопереключение Gemini при 429 и его цепочка моделей |
| `telegram` | да | сводки через необязательный скрипт уведомлений (см. ниже) |

## Уведомления — необязательный скрипт

Если есть `~/.bb/limit-guard/notify/send.py`, сторож вызывает его командой `python3 send.py --file <сводка.md> --note
<2–3 предложения> --quiet` при входе в стадию 1, 2 и при согласии (код выхода 0 — доставлено, 2 — защита скрипта не
пропустила файл). `--yes` сторож никогда не передаёт. Скрипта нет — уведомление не отправляется, сам сторож работает так
же; в `status` видно «уведомления не настроены».

## Аварийно выключить и как проверить

- `bb plugin disable limit-guard` — придержанные ходы сразу уходят, модели тредов остаются как есть.
- Тест-режим на одном треде: `bb limit-guard test --threads <id> --percent 95` и `test --off` (для Codex — `test codex …`).
  Живая проверка сторожа Codex в комплекте не выполнялась: смена effort и перестановка очереди проверены только тестами.
- Тесты: `npm test` (проверка логики, команд и сценариев на поддельном bb). Работает только на проверенном bb 0.46+:
  плагин опирается на данные лимитов самого bb (`usageLimits`) и на хук отправки сообщений.

Установка из Git:

```sh
bb plugin install "git:https://github.com/vibe-commerce-org/bb-vadim-setup.git@semver:~0.6.0" --subdirectory plugins/limit-guard
```
