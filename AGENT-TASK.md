# Задание агенту: настрой bb как у Вадима

Last Updated: 2026-10-21

Комплект 0.4.0 проверен на bb 0.46.1, macOS: 21.10 все девять плагинов собраны с нуля (`npm ci`,
`bb plugin build .`) и прошли тесты; до 11.10 комплект проверялся на 0.45.0. Windows проверена Вадимом 08.10.2026 на 0.45.0;
маршрут установки не уточнён. Linux-сервер описан по официальной документации,
на настоящем сервере не испытан.

## Как передать агенту

Распакуйте ZIP в постоянную папку **на компьютере, где работает сервер bb**,
и отправьте в тред bb:

> Настрой мой bb по комплекту в папке ПУТЬ_К_ПАПКЕ/bb-vadim-kit. Прочитай AGENT-TASK.md
> и выполни его. GUIDE.md — полная инструкция для человека, сверяйся с ней. Сохрани мои
> текущие настройки и правила. В конце покажи, что работает и что осталось проверить мне.

bb и хотя бы один агент уже должны работать. Вход в аккаунты выполняет пользователь;
в комплекте нет учётных данных.

## Порядок

Команды `bb …` выполняй во встроенном терминале bb или там, где доступен `$BB_CLI`; на Linux-сервере
по SSH — `npx --package bb-app bb …`. В обычном терминале команды `bb` нет. Ты работаешь в обычном
терминале (Claude Code или Codex вне bb) — сначала раздел «Если ты агент вне bb» ниже.

**Выбор пунктов.** Если пользователь дал списки «Поставить» и «Не ставить» с id из `catalog.json`,
выполняй шаги только для пунктов из «Поставить» — какой пункт к какому шагу относится, сказано в разделе
«Пункты комплекта». Без списков ставь всё, что в `catalog.json` отмечено `"default": true`.

1. Определи ОС **компьютера, где работает сервер bb**, и его папку данных:
   `bb --version`, `bb status --json`. Если твой тред работает на другом компьютере,
   сначала выясни, где сервер и какие у него пути. Не ставь плагины на один компьютер,
   рассчитывая, что сервер прочитает диск другого.
2. Проверь `node --version` (нужно 22.19 или новее), `npm --version`, `git --version`.
   Чего-то нет — предложи официальный установщик для этой ОС и подожди. bb и агентов
   сам не обновляй.
3. До изменений сохрани локально: изменяемые значения General, текущую тему и её файлы,
   состояние целевых плагинов, копию существующего `AGENTS.md`. Запиши дату и способ отката
   в локальный отчёт. Не экспортируй базы bb, `auth.json`, `.env`, cookie и хранилища паролей.
4. Сверь `MANIFEST.json`: у каждого файла размер и SHA-256, нет абсолютных путей, `..`,
   symlink наружу и лишних файлов. Если комплект — клон репозитория, `.git`, `.gitignore` и `scripts/`
   в манифест не входят: это служебные файлы репозитория.
5. Поставь профиль ОС по таблице ниже. Плагины лежат в `plugins/`: `markdown-view`, `office-preview`,
   `folder-links`, `floating-terminal`, `files-editor`, `russifier`, `repo-tag`, `pult`, `artifacts`; в bb
   они видны с суффиксом `_vibecom` (Markdown_vibecom, Office_vibecom, Folder links_vibecom,
   Terminal_vibecom, Explorer_vibecom, Русификатор_vibecom, Repo tags_vibecom, Пульт_vibecom,
   Важные артефакты_vibecom). Русификатору, тегу репозитория, Пульту и Артефактам нужен bb 0.46 или
   новее: на старом bb пропусти их и скажи почему.
   В папке каждого: `npm ci` (для `files-editor` и `floating-terminal` — `npm ci --ignore-scripts`), `bb plugin build .`,
   `bb plugin install <абсолютный путь папки> --yes`. Уже установленный плагин не дублируй:
   проверь `bb plugin list` и `bb plugin source <id>`. Если плагин с тем же ID стоит из другого
   источника — Floating Terminal из каталога или **Files editor из git** (`files-editor` из комплекта
   его заменяет), — покажи разницу и спроси, прежде чем делать `bb plugin remove <id>`: настройки
   удалённого плагина пропадут. Если плагин уже стоит из этой же папки комплекта (прошлый ZIP), не
   переустанавливай, а пересобери: `npm ci` (для `files-editor` и `floating-terminal` — `npm ci --ignore-scripts`),
   `bb plugin build .`, `bb plugin reload <id>` (ID — имя папки, не имя с `_vibecom`); сверь версию
   в `bb plugin list` (`floating-terminal@0.6.2`, `files-editor@0.1.6`, `russifier@0.2.0`, `pult@0.2.0`,
   `repo-tag@0.1.0`, `artifacts@0.1.0`, три просмотрщика — `@0.4.0`). Explorer_vibecom показывает
   Markdown через сервер Markdown_vibecom: без `markdown-view` его не ставь. Lockfile и версии не меняй. Предупреждение сборки о закреплённой версии SDK — норма;
   `bb plugin types` не выполняй.
6. Скопируй папку `theme/atom-one_vibecom` в каталог из `bb theme dir`, выполни
   `bb theme set atom-one_vibecom`, проверь `bb theme show`. Если там есть тема `atom-one` из прошлого
   комплекта (те же файлы под старым именем), предложи пользователю удалить её после проверки.
7. Примени выбранные общие настройки (список ниже) и перечитай их через CLI. Текущего агента,
   модель и effort пользователя не меняй.
8. Объедини `instructions/AGENTS.md` с `<папка данных bb>/AGENTS.md`: добавь блок между
   маркерами `<!-- bb-vadim-setup begin -->` и `<!-- bb-vadim-setup end -->`; при повторном
   запуске обновляй только его. Правила пользователя сохрани, противоречия покажи.
9. Открыватели файлов назначь по разделу 13 GUIDE.md, если тебе доступен интерфейс.
   Есть только CLI — перечисли, что пользователю закрепить в **Settings → Files → File openers**. `.html` и `.htm`
   → «Built-in preview» Explorer_vibecom закрепляет сам при загрузке bb на каждом устройстве; попроси
   пользователя обновить окно bb (⌘R) и страницу на телефоне. Остальной выбор хранится в браузере: на телефоне
   его закрепляют отдельно.
10. Модели (пути 2 и 3 GUIDE.md) — для выбранных провайдеров; без списков «Поставить» и «Не ставить»
    выбраны все три. Нужен агент Pi: его нет — предложи поставить (GUIDE.md, раздел 6, шаг 1) и дождись «да».
    Скопируй `models/pi/models.json` и `models/pi/auth.example.json` в `~/.pi/agent/`
    (`models.json`, `auth.json`), **не перезаписывая** существующие файлы: при наличии —
    покажи, какие блоки добавить. На macOS и Linux сразу выполни `chmod 600 ~/.pi/agent/auth.json`.
    Оставь в `models.json` только блоки выбранных провайдеров (Яндекс, Cloud.ru, LM Studio).
    - **Ключа нет — не останавливайся.** Шаблон с заглушками оставь на месте и одной строкой скажи, что
      и куда вписать: для Яндекса — API-ключ вместо `YOUR_YANDEX_API_KEY` в `auth.json` и ID каталога
      вместо `YOUR_FOLDER_ID` в `models.json` (два места); для Cloud.ru — Key Secret сервисного аккаунта
      вместо `YOUR_CLOUD_RU_KEY_SECRET` в `auth.json`; где взять — GUIDE.md, раздел 6, шаг 2. Предупреди,
      что до ключа эти модели видны в списке Pi и отвечают ошибкой. Дальше — следующий шаг.
    - Ключи и ID каталога пользователь вписывает сам; не проси вставлять ключи в чат и не читай
      `auth.json` после заполнения.
    - **LM Studio.** Блок `lmstudio` из шаблона подключи. LM Studio не стоит — предложи официальный
      установщик с lmstudio.ai и дождись «да». **Перед скачиванием модели — отдельный вопрос:** какую
      (GUIDE.md, раздел 7), сколько гигабайт она займёт по данным LM Studio и хватит ли места и памяти.
      Без отдельного «да» модель не скачивай; нет «да» — блок оставь и скажи, что включить позже.
11. Проверь сборки и `npm test` в папке каждого поставленного плагина. В `floating-terminal` запускай только
    `npm test`: другие его скрипты шлют команды в открытый терминал. Из раздела 19 GUIDE.md
    выполни пункты 2–4; остальные (новый и дочерний тред, вид Markdown, документы в Explorer_vibecom,
    офисные файлы, вкладка Terminal_vibecom, ссылка на папку, очередь по Enter, телефон) внеси в список того, что пользователь
    проверит сам. Соблюдай текущие разрешения: не отключай sandbox и не повышай
    режим прав.

## Пункты комплекта

Id — как в `catalog.json` и на странице выбора. Пункт, которого нет в таблице, не выполняй: остановись и
спроси. Если выбранному пункту нужен пункт из «Не ставить» (поле `requires` в каталоге), спроси пользователя.
Пункт, который по таблице «Профили ОС» не подходит к его ОС, пропусти и скажи почему.

| Id | Что сделать |
|---|---|
| `theme` | шаг 6 |
| `markdown-view`, `office-preview`, `folder-links`, `floating-terminal`, `files-editor` | шаг 5 для папки с этим именем и настройки плагина из «Общих настроек»; `files-editor` требует `markdown-view` |
| `russifier` | шаг 5 для `plugins/russifier`; интерфейс сразу становится русским, effort и режимы доступа остаются по-английски. Скажи, как вернуть английский: `bb plugin config russifier set language en` |
| `repo-tag` | шаг 5 для `plugins/repo-tag`; настройки по умолчанию (3 символа) |
| `pult` | шаг 5 для `plugins/pult`; маркер «⏸ Ход за тобой» в ответах агентов даёт пункт `rules` — не выбран, скажи, что Пульт будет распознавать ход только по тексту |
| `artifacts` | шаг 5 для `plugins/artifacts`; это бета — перескажи пользователю «что пока не работает» из `plugins/artifacts/README.md` |
| `rules` | шаг 8 |
| `phone` | Connect сам не подключай: проверь `bb connect status` и покажи пользователю шаги из `PHONE.md`, разделы 1–2 |
| `settings-queue`, `settings-ui`, `provider-retry` | команды с этим id из «Общих настроек» |
| `settings-hotkeys` | переход между панелями — Cmd+Shift+стрелки (на Windows и Linux — Ctrl+Shift): `bb settings keyboard set` для `pane.focus.left`, `pane.focus.right`, `pane.focus.up`, `pane.focus.down`; формат сочетания сверь с `bb settings keyboard list --json`. Не получилось — покажи, что закрепить в **Settings → Keyboard** |
| `keep-awake` | `bb keep-awake enable` (macOS, Windows) |
| `models-yandex`, `models-cloudru`, `models-lmstudio` | шаг 10 только для выбранных провайдеров |

## Если ты агент вне bb

Тебя запустили в обычном терминале (Claude Code или Codex), а bb ещё нет:

1. Поставь bb по GUIDE.md, часть 1, блок для ОС пользователя. Перед установкой каждой программы скажи, что
   ставишь и откуда, и дождись «да». В аккаунты входит пользователь сам.
2. Дождись, пока пользователь запустит bb и увидит в нём своего агента.
3. Дальше bb настраивает агент внутри bb: в обычном терминале команды `bb` нет. Выдай пользователю одним
   блоком промпт для первого треда bb: «Установи мне bb как у Вадима», путь к папке комплекта, «Прочитай
   AGENT-TASK.md и выполни его для моего выбора» и те же списки «Поставить» и «Не ставить».

## Общие настройки

```text
# settings-queue
bb settings general steerActiveThreadOnEnter false
# settings-ui
bb settings general showKeyboardHints true
bb settings general showDiagnosticEvents false
bb settings general confirmThreadArchive true
# provider-retry
bb plugin config provider-retry set maximumWait "24 hours"
# floating-terminal
bb plugin config floating-terminal set fontSize 13
# files-editor
bb plugin config files-editor set openDocumentsIn "This panel"
```

Команды `bb plugin config floating-terminal …` и `bb plugin config files-editor …` выполняй только после
установки этих плагинов из комплекта. Внешний File Manager из прошлых выпусков не ставь: файлы, загрузку
и скачивание даёт Explorer_vibecom. Если File Manager уже стоит, не удаляй его без просьбы пользователя.
Сочетание Ctrl+` для вкладки Terminal_vibecom задаёт bb
(команда «Terminal_vibecom: open in side panel», Settings → Keyboard) — отдельной настройки плагина нет. Concurrency оставь
автоматическим.

## Чего не делать

- Не меняй телеметрию, аккаунты, ключи, глобальные разрешения и текущую модель.
- Не подключай Connect, не выставляй порты наружу, не создавай публичных адресов.
- Не клонируй репозитории без выбора пользователя; не делай commit, push, публикацию,
  покупки и новые треды в рамках этой установки.

## Отчёт

Версии bb, Node.js и ОС; какие плагины `running`, какие пропущены и почему; результаты сборок
и тестов; где резервные копии и как откатить; какие модели ждут ключа и куда его вписать. Отдельно — что
пользователю проверить глазами (открыватели, вид Markdown, документы в Explorer_vibecom, вкладка
Terminal_vibecom и терминал с телефона, русский интерфейс, теги у тредов, страница «Пульт», вкладка
«Важные артефакты»). Установку у пользователя не называй проверенной,
пока не прошли её собственные проверки.
